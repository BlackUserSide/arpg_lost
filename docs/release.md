# Збірки й релізи: як це працює

Усе робить GitHub Actions (`.github/workflows/ci.yml`). Руками на GitHub треба лише один раз налаштувати Pages і секрет, а для релізу — поставити тег.

| Подія | Що відбувається | Де результат |
|---|---|---|
| Pull Request у `main` | перевірки: типи, lint, тести, збірка | вкладка **Actions**, позначка біля PR |
| Push (злиття) у `main` | перевірки → **тестова збірка з бета-замком** → GitHub Pages | https://blackuserside.github.io/arpg_lost/ |
| Тег `v*` (напр. `v0.5.0`) | перевірки → **збірка для CrazyGames без замка** → ZIP | **Releases** → реліз `v0.5.0` → файл `arpg-lost-v0.5.0.zip` |

## Один раз: налаштування на GitHub

1. **Секрет з кодом доступу.** Settings → Secrets and variables → Actions → **New repository secret**.
   Name: `BETA_CODE`, Secret: код, який отримають тестувальники (регістр і пробіли не важать: «Ember Gate» = «embergate»).
   Беріть **довгу випадкову фразу** (4–5 випадкових слів або 20+ випадкових символів): сіль і хеш у збірці публічні, тож короткий код чи звичайне слово можна підібрати перебором офлайн.
   Код лише з пробілів збірка відхиляє з помилкою (інакше вийшла б збірка без замка).
   Без цього секрету тестова збірка **не публікується** (крок падає з поясненням): репозиторій публічний, адресу Pages легко вгадати, тож збірка без замка відкрила б бету всім.
2. **Pages.** Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Після злиття в `main` (або Actions → CI → **Run workflow** на `main`) за 2–3 хвилини гра з'явиться за адресою вище. Посилання на сайт є й у самому запуску: Actions → CI → job «Test build → GitHub Pages».

Змінити код: оновіть секрет `BETA_CODE` і перезапустіть Actions → CI → Run workflow на `main`. Тестувальники введуть новий код один раз (старий запам'ятований доступ перестане діяти).

## Бета-замок

- Вікно «Закритий бета-тест — не поширюйте посилання; прогрес можуть скинути» з полем коду (мова — як у грі: збережена або мова браузера).
- Правильний код запам'ятовується на пристрої (в тому ж сховищі, що й сейви); неправильний — коротка помилка, без блокування.
- Є **лише** в тестовій збірці на Pages. Локально (`npm run dev`) і в ZIP для CrazyGames замка немає — його коду навіть немає в збірці.
- Це замок від випадкових людей із посиланням, **не захист**: код гри відкритий, у збірці лише солений SHA-256 коду, а не сам код. Сіль і хеш публічні, тому код — довга випадкова фраза, а не коротке слово (коротке підбирається перебором).
- Після збірки CI перевіряє, що замок справді потрапив у збірку (файл `dist/assets/betaGate-*.js`); якщо ні — Pages не оновлюється.

## QA-попап

- Тестовий режим (7 натискань на номер версії в меню) є в `npm run dev` і в тестовій збірці на Pages — **лише в закритій беті**.
- У ZIP для CrazyGames його немає, навіть коду в збірці (`__QA_MODE__` = false). За замовчуванням QA вмикається там, де є бета-замок; змінна `QA_MODE=1` / `QA_MODE=0` примусово вмикає / вимикає (реліз у CI збирається з `QA_MODE=0`).

## Реліз для CrazyGames

1. Версія в `package.json` має збігатися з тегом (тег `v0.5.0` ⇔ `"version": "0.5.0"`), інакше реліз зупиниться з поясненням. Версію піднімаємо в гілці й зливаємо в `main` як звичайно.
2. Поставити тег на `main`:
   - через git: `git tag v0.5.0` → `git push origin v0.5.0`;
   - або на сайті: **Releases → Draft a new release → Choose a tag** → ввести `v0.5.0` (Create new tag on publish, target `main`) → **Publish release**.
3. За кілька хвилин у релізі з'явиться `arpg-lost-v0.5.0.zip` (у корені архіву — `index.html`). Розмір ZIP і збірки видно в підсумку запуску (Actions → CI → цей запуск → Summary).
4. Завантажити ZIP у CrazyGames Developer Portal і перевірити в Preview — вручну.

## Локально

- `npm run build` — збірка без замка і без QA-попапу (як для CrazyGames).
- Перевірити збірку із замком: PowerShell `$env:BETA_CODE='мій код'; npm run build; Remove-Item Env:BETA_CODE`, потім `npx vite preview`. Код перевіряється через Web Crypto, тож відкривати треба з `localhost` або https (не з IP у локальній мережі по http).
